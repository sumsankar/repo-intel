Executive Summary
hrms-angular is an Angular 17 single-page application for an internal Human Resource Management System (HRMS), covering employee profiles, attendance, leave, timesheets, payroll, and org management. The project is in reasonably good shape: it has a working Jenkins CI/CD pipeline, Docker containerisation, Husky pre-commit hooks enforcing Prettier and ESLint, and a 13% test spec ratio. The primary issues are a critically outdated pdfjs-dist library (CVE-2024-4367 — arbitrary JavaScript execution via malicious PDFs), Microsoft Teams webhook URLs committed in the Jenkinsfile enabling unauthorised posts to internal channels, a cluster of god-component files exceeding 1,500–2,900 lines, and no test execution step in the CI pipeline. The single most important fix is upgrading pdfjs-dist from 2.10.377 to 4.2.67+ to eliminate a remote-code-execution vector in PDF rendering.

🚨 Critical & High Priority Findings
  • HighDependency pdfjs-dist@^2.10.377 is pinned to a version from 2021. CVE-2024-4367 (CVSS 7.1 — arbitrary JavaScript execution via maliciously crafted PDF) affects all versions before 4.2.67. The app renders PDFs from user-uploaded files via the consent-documents component, making this an exploitable vector.
    package.json line 55 — "pdfjs-dist": "^2.10.377"
    Fix: Upgrade to pdfjs-dist@^4.2.67. Note: this is a major version jump with a breaking API change — migrate from pdfjsLib.getDocument() to the new module-based API. Audit the pdfWorkerPath config to point to the matching worker version.
  • HighSecurity Two Microsoft Teams incoming webhook URLs are hardcoded in the Jenkinsfile post-build notification block. Anyone with read access to this repository can POST arbitrary messages — including phishing links or spoofed deployment alerts — to the internal Teams channels used for dev and UAT notifications.
    Jenkinsfile lines ~140–145 — webhookMap = [dev: 'https://paltech0.webhook.office.com/…', uat: '…']
    Fix: Move the webhook URLs to Jenkins credentials store (withCredentials([string(credentialsId: 'teams-webhook-dev', variable: 'TEAMS_HOOK_DEV')])) and remove the hardcoded values from the Jenkinsfile. Rotate the existing webhook URLs in Microsoft Teams to invalidate the committed ones.

🏗️ Architecture

Summary: The Angular 17 project follows best-practice feature-module organisation with lazy loading, a clear separation between smart components, services, models, guards, and validators, and a smart runtime-config pattern that injects environment-specific JSON at deploy time rather than baking in per-environment builds.

  • Project type: Angular 17 SPA — feature-module architecture with lazy routing (auth / hrms / shared / call-back / unauthorized)
  • Direct dependencies: 37 production / 18 devDependencies = 55 total (moderate; within acceptable range)
  • Monorepo: Single-app workspace — not a monorepo
  • Layered structure: ✅ Clear — modules → components → services (56 services) → models → guards → validators · Runtime config via /assets/config/app-config.json injected at container startup
  • MediumPatterns The GitLab CI pipeline (.gitlab-ci.yml) runs only a PR Agent AI review stage — it performs no build, lint, or test steps. Real quality enforcement is handled exclusively by Jenkins, which is not triggered on Merge Requests. A broken MR can be merged as long as the AI review passes.
    .gitlab-ci.yml (entire file — only stage: pr_agent)
    Fix: Add a build stage to .gitlab-ci.yml that runs npm ci && npm run build-prod on every MR, in addition to the existing PR Agent review. This ensures the production build is always verified before merge.
  • MediumSecurity bypassSecurityTrustResourceUrl() is called in 3 places inside the consent-documents components to embed PDF iframes. If the fileUrl variable can be influenced by user-supplied or server-returned data without strict validation, this bypasses Angular's built-in XSS protection.
    consent-documents.component.ts:250, 326 · document-status.component.ts:574
    Fix: Validate that all URLs passed to bypassSecurityTrustResourceUrl originate from a known set of internal domains (e.g., match ssoBaseUrl or baseURL from config) before trusting them. Add unit tests to the spec files covering these code paths.
  • LowArchitecture The pre-push Husky hook runs npm run build-push (a full AOT development build) on every push. This blocks the push for 60–90 seconds and will fail on slow machines or CI runners that use SSH push, making it an unreliable gate that developers may disable.
    .husky/pre-push
    Fix: Replace the pre-push build check with a faster type-check: npx tsc --noEmit. Move the full build validation to the Jenkins pipeline stage which is the authoritative quality gate.
  • LowArchitecture Three parallel timesheet implementations coexist — time-sheet, time-sheet-v2, and time-sheet-v3 — each duplicating routing, services, and component logic. The original version appears to be dead code that was never removed.
    src/app/modules/hrms/me/ · src/app/modules/hrms/my-team/ (all three time-sheet* directories)
    Fix: Identify and delete the unused timesheet version(s). A quick check of which routes are registered in the router module and which components are still referenced in the routing config will identify dead code candidates.
🔒 Security

Risk Level: 🟠 HIGH — Known CVE in active PDF library + committed webhook URLs

Summary: No database credentials or private keys are committed; the app correctly externalises environment config. However, the pdfjs-dist version in use has a publicly known JavaScript execution CVE, Teams webhook URLs are in source, and Angular's security model is partially bypassed for PDF embedding without visible URL validation.

  • MediumConfig An Unleash feature-flag client key (hrms:development.87ac9fdac02ec9a3469ee508c76513d43a1fddd15048a354eb397424) is committed in the default app-config.json. While Unleash frontend keys are not privileged secrets, committing a real key means the development feature-flag environment is permanently exposed, allowing anyone to read which flags are enabled and potentially toggle them if the Unleash server lacks key-level access control.
    src/assets/config/app-config.json — unleash.clientKey
    Fix: Replace the committed value with a placeholder (e.g., "clientKey": "REPLACE_AT_DEPLOY_TIME"). Inject the real key via the same Jenkins configFileProvider mechanism used for the rest of app-config.json. Rotate the existing key in the Unleash admin console.
  • LowHygiene No SECURITY.md and no Dependabot/Renovate configuration. There is no process for team members to report vulnerabilities, and no automated scanning will surface the next CVE in an npm dependency.
    Repository root — .github/SECURITY.md and dependabot.yml missing
    Fix: Add a SECURITY.md with a security contact email and a .gitlab/dependabot.yml (or Renovate config) to automatically raise MRs for outdated dependencies on a weekly schedule.

  • MediumCI The Jenkins pipeline has no test stage. The 109 existing unit tests are never executed in CI, so regressions in auth, guards, or service logic can reach main undetected.
    Jenkinsfile — stages block (no ng test call)
    Fix: Add a Test stage before the Docker build stage: sh "npm run test -- --watch=false --browsers=ChromeHeadless". Configure karma.conf.js to output JUnit XML and archive it as a Jenkins test result.
  • LowDocker The Dockerfile uses FROM nginx:alpine without pinning to a specific nginx version (e.g., nginx:1.27-alpine). If the nginx:alpine tag is updated to a new major version, future builds may silently change behaviour or introduce regressions.

    Fix: Pin to a specific version: FROM nginx:1.27-alpine. Schedule regular version bumps via Renovate or manual quarterly review.
  • LowDocker The Dockerfile has no USER directive — nginx runs as root inside the container. This violates container security best practices and increases blast radius if the container is compromised.
    Dockerfile (no USER instruction)
    Fix: Switch to nginx:1.27-alpine-slim which ships with a pre-configured non-root nginx user, or add an explicit USER nginx directive after configuring nginx to bind on port 8080 instead of 80.
  • LowHygiene No CHANGELOG.md. With multiple deploy environments (dev, UAT) and a Jenkinsfile tracking build numbers, there is no human-readable record of what changed between releases.
    Repository root — CHANGELOG.md missing
    Fix: Adopt Conventional Commits and add a CHANGELOG.md. Consider configuring conventional-changelog-cli or semantic-release as a post-deploy step in Jenkins.
📦 Dependencies

Summary: Angular 17.3.5 is current and well-supported, but pdfjs-dist is three major versions behind with an active CVE, moment is deprecated, and xlsx carries historical prototype-pollution advisories.

  • MediumStaleness moment@^2.29.4 — the moment.js team declared the library feature-frozen and recommends migration. No new security fixes will be issued. The codebase uses it for date formatting across the timesheet and leave modules.
    package.json — "moment": "^2.29.4"
    Fix: Migrate to date-fns or Angular's built-in DatePipe/formatDate. Angular Material already bundles @angular/material-moment-adapter — switch to @angular/material-date-fns-adapter as a drop-in replacement.
  • LowCVE xlsx@^0.18.5 (SheetJS Community Edition) — the community edition is no longer receiving security updates; multiple prototype-pollution advisories exist in the 0.x line. The project uses it for bulk-upload Excel parsing.
    package.json — "xlsx": "^0.18.5"
    Fix: Evaluate migrating to exceljs (actively maintained, MIT) or the commercial SheetJS Pro if Excel compatibility is critical. Ensure Excel upload input is validated server-side and not trusted client-side.
  • LowHygiene No Renovate or Dependabot configuration. Angular 17 has a 12-month LTS support window; without automated dependency tracking, upgrades to Angular 18/19 will be discovered reactively rather than planned.
    Repository root — no .renovaterc or .gitlab/dependabot.yml
    Fix: Add a Renovate config (renovate.json) with Angular schematic support so ng update-compatible upgrades are automatically proposed as MRs. Group Angular packages to avoid partial upgrades.
