Executive Summary
McKissock StudentAPI is a .NET Framework 4.0 / Mono REST API built on ServiceStack 4.0.40, serving as the backend for a real-estate education platform's student management system, deployed to AWS ECS via CircleCI and Docker. The project has a functional CI/CD pipeline and a recognizable layered service architecture, but is in a critically unhealthy security state: two complete sets of AWS credentials (key ID + secret) are committed in plaintext across three source files, giving any reader with repository access full programmatic control over the production AWS ECR registry and ECS infrastructure. The single most important action is to immediately rotate all three exposed AWS key IDs, remove them from every source file, and replace them with CircleCI encrypted environment variables backed by AWS Secrets Manager — everything else is secondary until this credential leak is contained.

🔒 Security

Risk Level: 🔴 CRITICAL — Live AWS credentials committed to version-controlled source files

Summary: Two distinct complete AWS credential pairs are present in plaintext across three committed files; either set grants an attacker full programmatic access to push Docker images to production ECR and update running ECS services. A Polaris/Synopsys SAST scan is configured (positive signal) but no SECURITY.md or Dependabot exists to close the vulnerability disclosure and auto-patching gaps.

  • Medium [injection] Raw SQL string interpolation with database-derived integer IDs is used in test cleanup code. The pattern signals insufficient parameterized-query discipline and risks spreading to production service code.
    src/McKissock.StudentApi.Tests/CredentialTest.cs — lines 51, 267–268
    Fix: Replace ExecuteSql($"… {studentId}") with a parameterized overload. Establish a team coding standard: no string interpolation in any SQL context, test or production.
  • Medium [hygiene] No SECURITY.md exists at the repository root or under .github/. Security researchers and internal staff have no defined channel to report vulnerabilities responsibly.
    Repository root / .github/ — SECURITY.md absent
    Fix: Add SECURITY.md specifying a disclosure contact email and a target response-time SLA (e.g. acknowledge within 48 hours, patch within 30 days).
  • Low [config] The .gitignore does not cover .env or *.env.* patterns. A developer who introduces a local .env file for secrets would commit it by default.
    .gitignore (root)
    Fix: Append .env, .env.*, *.key, and *.pem to .gitignore as a precautionary baseline.
⚙️ DevOps

Summary: CI/CD is well-structured with CircleCI handling branch-to-environment promotion (dev → test → stage → prod) and Docker images version-tagged per build, but the pipeline never runs tests, the Dockerfiles run as root, and there is no .dockerignore to prevent local artifacts from entering the image.

  • ✓ CI/CD pipeline (CircleCI v2 with build + 4 deploy jobs)
  • ✗ Tests in CI (no NUnit step in build job)
  • ✓ Docker (Dockerfile + ECR push pipeline)
  • ✓ IaC (ECS task definition JSON, buildspec.yml, Polaris SAST config)
  • ✓ README (readme.md — substantive, 80+ lines with setup and deployment docs)
  • ✗ LICENSE (no LICENSE file)
  • ✗ CHANGELOG (no CHANGELOG.md)
  • ✓ Lock file (NuGet packages.config present)
  • Medium [docker] The main Dockerfile pulls a base image using a parameterized tag (:latest variant) without a pinned SHA digest, so builds are not reproducible if the upstream image changes.
    Dockerfile — line 2 (FROM … :latest)
    Fix: Pin the ECR base image to a specific version tag or SHA256 digest in the build arg default. Rotate the pin on a deliberate cadence.
  • Medium [docker] Neither Dockerfile nor docker/Dockerfile.base includes a USER instruction, so the container runs as root. This increases blast radius if the application process is compromised.
    Dockerfile · docker/Dockerfile.base
    Fix: Add RUN adduser --disabled-password appuser && USER appuser before the CMD instruction in both Dockerfiles.
  • Low [docker] No .dockerignore file is present. The COPY ./src ./src instruction may include local build artifacts, IDE state files, or config overrides in the image layer.
    Repository root — .dockerignore absent
    Fix: Add .dockerignore excluding **/bin/, **/obj/, .vs/, *.user, *.suo, and environment-specific config transforms.
  • Low [hygiene] No CHANGELOG.md exists, so there is no auditable record of what changed between releases — complicating incident root-cause analysis and customer communication.
    Repository root — CHANGELOG.md absent
    Fix: Adopt conventional commits and add standard-version or release-please to auto-generate changelogs on each release tag.
